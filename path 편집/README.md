# PAC 왕복 경로 편집 프로토타입

정지한 로봇의 **예정 경로를 수정하는 인터페이스**를 순수 Python으로 모사합니다. 가상 카메라 영상 평면에서 경로점을 선택하고, 마우스 이동과 깊이 입력을 3D 손 이동으로 바꾸어 주변 경로를 수정합니다. 원본·확정·편집·핀치 미리보기를 구분하며, 경로 검사에 통과한 편집 데이터만 JSON으로 저장합니다.

이번 구현에는 ROS, 실제 로봇 실행, 카메라·음성·손 인식 API가 없습니다. 화면의 **“경로 검사 통과 · 로봇 검증 미수행”**은 프로토타입 데이터의 기하·시간 검사 결과입니다. 로봇 실행 승인이 아닙니다.

## 설치와 실행

Python 3.10 이상을 사용합니다. `python` 명령이 없는 환경에서는 최초 가상환경 생성에 `python3`를 사용하세요.

명령은 이 README가 있는 폴더에서 실행합니다. 협업 저장소의 최상위에서 시작한다면 먼저 `cd "path 편집"`으로 이동하세요.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
python -m pac_path_editor --config configs/demo.json
pytest -q
```

ROS를 미리 source한 셸에서는 외부 `PYTHONPATH`의 pytest 플러그인이 가상환경에 유입될 수 있습니다. 이 프로젝트는 ROS를 사용하지 않으므로 그런 환경에서는 `env -u PYTHONPATH python -m pytest -q`로 검사하거나 새 셸에서 실행하세요. 설치 시 무관한 ROS 패키지 의존성 경고가 나면 `env -u PYTHONPATH python -m pip install -e ".[dev]"`를 사용합니다.

일반 왕복 직선이 기본입니다. 가는 길만 중앙이 10 cm 솟고 오는 길은 직선인 데모:

```bash
python -m pac_path_editor --config configs/demo.json --demo bump
```

GUI가 없는 환경에서 초기화·렌더링 및 이미지 저장:

```bash
python -m pac_path_editor --config configs/demo.json --demo bump \
  --headless --screenshot output/bump.png
```

한국어 지원 폰트가 있으면 한국어 UI를 사용하고, 없으면 영문 UI로 전환합니다. `--language en`으로 영문을 지정할 수도 있습니다. 주 화면은 2D 가상 카메라이며 경로를 구분하려고 실제 좌표를 옮기지 않습니다.

## 편집 조작

| 조작 | 동작 |
|---|---|
| `E` / 편집 시작 | 확정 경로를 복사해 편집 시작 |
| `1` / 함께 | 가는 길·오는 길을 같은 원본 대응 위치에서 함께 수정 (기본) |
| `2` / 가는 길 | 가는 길만 수정 |
| `3` / 오는 길 | 오는 길만 수정 |
| 경로 근처에서 왼쪽 누름 | 화면상 최근접 샘플점에 핀치 시작 |
| 왼쪽을 누른 채 이동 | 현재 깊이의 가상 손을 카메라 모델로 3D 변환 |
| 드래그 중 휠 위 / `PageUp` | 가상 손을 카메라 쪽으로 1.5 cm 이동 |
| 드래그 중 휠 아래 / `PageDown` | 가상 손을 카메라에서 멀어지게 1.5 cm 이동 |
| 왼쪽 해제 | 이번 핀치 전체를 편집 이력 하나로 기록 |
| `Esc` | 진행 중인 핀치만 취소 |
| `Ctrl+Z` / 실행 취소 | 마지막 완료된 핀치 또는 원본 복원을 취소 |
| `Ctrl+Y` / 다시 실행 | 취소한 편집을 다시 적용 |
| `R` / 원본 복원 | 두 경로와 수정 기록을 원본으로 복원; 실행 취소 가능 |
| `C` / 편집 취소 | 이번 편집 세션을 버리고 확정 경로로 복귀 |
| `F` / 수정 완료 | 전체 candidate 검사, 통과하면 확정·JSON 저장 |
| `I` | 검사 수치 등 개발 확인 정보 표시 전환 |

버튼과 키보드는 동일한 `Editor.execute_command`를 호출합니다. 핀치를 유지하는 동안 모드 전환, 완료, undo/redo/reset을 요청하면 먼저 핀치를 종료하라는 안내를 표시합니다. 깊이 이동 방향은 로봇의 Z축이 아니라 **카메라의 앞뒤 방향**이며 마우스 이동도 픽셀을 미터로 직접 사용하지 않습니다.

선택은 18 px 반경 내의 **2D 투영 거리**만 사용합니다. 완전 동률이면 `outbound` → `return` → 각 경로의 작은 실행 배열 인덱스 순으로 선택합니다. 겹친 직선에서 오는 길만 선택하려면 `3`을 누르세요. 함께 모드에서는 어느 한쪽만 선택 반경 안에 있어도 시작하고 다른 쪽을 동일한 원본 `xi`에서 보간합니다. 대응점에 선택 반경을 다시 적용하지 않습니다. 선택 경로와 `xi`는 핀치 해제까지 고정됩니다.

마우스가 영상 영역 밖으로 나가거나 손/깊이 입력이 유효하지 않으면 마지막 유효한 미리보기를 유지합니다. 창 안에서 해제하면 마지막 유효 결과를 기록합니다. **포인터가 창 밖으로 나가거나 창을 닫으면 진행 중인 핀치를 취소**합니다. 완료하지 않은 세션은 자동 저장하지 않습니다. 새 수정 후에는 이전 redo 분기를 삭제합니다.

## 화면 읽기

- 실선은 가는 길, 점선은 오는 길입니다. 화살표는 실행 방향이며 출발점과 목표점은 항상 고정됩니다.
- 핀치 중 편집 대상의 시작 경로는 불투명 검은 선, 미리보기는 높이 색상으로 표시합니다. 비대상은 현재 경로만 반투명 높이 색상으로 표시합니다. 핀치가 없으면 검은 비교선을 그리지 않습니다.
- 노란 원은 선택 중심, 마름모는 함께 모드 대응 중심입니다. 옅은 굵은 띠는 국소 영향 구간입니다.
- 파란 점선 화살표는 제한 전 요청 이동입니다. 실제 적용 결과가 다르면 주황색 화살표도 표시합니다. 오른쪽에 요청·실제 변위를 cm로 표시합니다.
- 검사 실패 위치는 빨간 X, 문제 구간은 빨간 띠로 표시합니다. 실패한 편집 경로를 화면에 유지해 계속 수정할 수 있습니다. 검사 결과는 해당 revision에만 유효하며 경로가 바뀌면 무효화합니다.
- 두 경로와 수정 전후는 같은 높이 색상 범위를 사용합니다. `colors.mode`는 `fixed`(기본) 또는 `path`이며, `path`에서도 핀치 중 범위는 시작 시점에 고정됩니다.

## 저장과 불러오기

저장 경로는 CLI로 지정합니다. 기존 파일은 수정 완료 검사에 통과한 뒤 임시 파일→교체 방식으로 갱신합니다. 핀치 해제나 원본 복원만으로 기존 저장 파일을 바꾸지 않습니다.

```bash
python -m pac_path_editor --config configs/demo.json --demo bump \
  --save output/my-session.json
# UI에서 편집 후 F
python -m pac_path_editor --load output/my-session.json \
  --save output/my-session-revised.json
```

`--load`는 저장된 원본·xi·설정·correction·검사 결과를 불러와 한 번만 재구성합니다. `--config`를 함께 지정하면 저장 설정과 일치하는지 엄격히 검사합니다. `--demo`는 새 원본 생성용이므로 `--load`와 함께 사용할 수 없습니다. 잘못된 schema, 단위, 설정 충돌, 오래된 revision의 검사 결과를 조용히 무시하지 않습니다. 저장 파일에는 로봇 검사 `NOT_EVALUATED`와 `prototype_only`가 포함됩니다. 파일 저장 오류가 나면 위치를 확인하고 `F`로 재시도할 수 있습니다.

```bash
python -m pac_path_editor --load output/my-session.json \
  --headless --screenshot output/reloaded.png
```

## 시험용 파라미터

아래 수치는 동작을 눈으로 검증하기 위한 **데모 시험값**이며 장비 기준의 확정 운용값이 아닙니다. 특히 실제 공간 gate의 방식과 반경은 장비 검증 후 정해야 합니다. 전체 설정은 [configs/demo.json](configs/demo.json)에 있습니다.

| 설정 | 시험값 | 시험값을 사용한 이유 |
|---|---:|---|
| 출발·목표 위치 | `(0,0,0.12)` → `(0.6,0,0.12)` m | 작업대 위 60 cm 왕복을 화면에 표시 |
| 초기 편도 시간·샘플 간격 | 3 s / 0.03 s | 충분한 대응점과 가벼운 상호작용 |
| 선택 반경 | 18 px | 화면에서 마우스로 잡기 쉬운 반경 |
| 경로를 따른 국소 영향 길이 | 0.22 m | 중앙 주변의 휘어짐이 분명하게 보이는 범위 |
| 공간 gate | 비등방 `Rxy=0.22`, `Rz=0.16` m | 수평·수직 재사용 반경이 분리되는 사례 검증 |
| 등방 gate 대안 | `R0=0.18` m | `gate.mode="isotropic"`로 비교 가능 |
| gate 핵심 비율 `alpha` | 0.5 | 안쪽 절반 완전 적용, 바깥쪽 cosine 감쇠 |
| 개별 손 이동 상한 | 0.15 m | 큰 드래그의 방향을 보존하며 norm 제한 |
| 원본 대비 누적 총변형 상한 | 0.30 m | 여러 드래그 누적과 saturation 사례 확인 |
| 최소 실효 수정량 | 0.001 m | 1 mm 미만의 미세 입력을 이력에 남기지 않음 |
| 끝점 보호 길이 | 0.08 m | 끝점 주변이 부드럽게 고정되는지 확인 |
| EE 최대 속도 | 0.35 m/s | 경로가 길어지면 시간이 늘어나는지 확인 |
| 시간 안전 배율·단축 정책 | 1.01 / 단축 안 함 | 속도 한도 여유 및 기본 시간 유지 |
| 높이 색상 고정 범위 | -0.15 ~ +0.65 m | 위·아래 수정에 공통 색상 척도 유지 |
| 가상 카메라 | 1000×700 px, `fx=fy=900` px | 위에서 비스듬히 보는 작업대 투영 |
| 깊이 입력 배율 | 0.015 m/step | 휠·키로 미세한 앞뒤 수정 |
| 수치 허용오차 | `1e-8` | 부동소수점 재현·검사 허용치 |

국소 영향 길이는 **이번 경로를 따라** 움직일 범위이며 공간 gate는 **저장된 수정의 다른 원본에 대한 재사용** 범위입니다. 같은 원본에서 새로 입력한 correction에는 gate 1을 유지하므로 이미 변형된 경로가 원본에서 멀어졌다는 이유로 새 드래그가 사라지지 않습니다. 흡수·raw field·끝점 감쇠·포화 처리의 정의와 제약은 [DESIGN.md](DESIGN.md)에 설명합니다.

수정 완료 시 기하 경로와 별도로 실행용 경로를 다시 샘플링합니다. 호 길이에 대한 min-jerk 진행률을 사용하며, 길이 변화와 최대 속도를 고려해 시간을 늘리고 실제 시간 샘플의 속도도 검사합니다. 기본 정책은 경로가 짧아져도 초기 시간보다 단축하지 않습니다.

## 사람이 수행할 데모 확인 순서

1. `--demo bump`로 실행하고 가는 길만 솟아 있는지 확인합니다. `E`, `1`을 누릅니다.
2. 솟은 가는 길 중앙을 누릅니다. 오는 길이 선택 반경 밖에 있어도 대응점 마름모가 표시되는지 확인합니다.
3. 아래로 드래그합니다. 두 중심에 같은 base-frame 이동이 적용되면서 가는 길의 솟음은 줄고 오는 길도 아래로 휘는지 확인합니다. 휠로 카메라 깊이 방향 이동을 추가합니다.
4. 핀치를 유지하며 `2`를 눌러 모드가 바뀌지 않는지, `F`를 눌러 먼저 핀치를 끝내라는 안내가 나오는지 확인합니다. 놓은 뒤 두 경로가 동시에 유지되는지 확인합니다.
5. `Ctrl+Z`, `Ctrl+Y`로 두 경로가 한 번에 복원되는지 확인합니다. `R` 뒤 실행 취소로 correction과 경로가 함께 복원되는지도 확인합니다.
6. `2`로 가는 길만 수정하고 오는 길이 변하지 않는지 확인합니다. 끝점 가까운 곳과 큰 드래그로 요청 화살표와 실제 적용 화살표가 달라지는지 확인합니다. `Esc`로 진행 중인 핀치를 취소합니다.
7. `F`로 검사·저장합니다. “경로 검사 통과 · 로봇 검증 미수행”과 늘어난 실행 시간을 확인합니다. 위 불러오기 명령으로 저장 전과 같은 경로가 나타나는지 확인합니다.
8. 새 편집 후 `C`로 확정 경로로 돌아오는지 확인합니다. 창 이탈은 진행 중 핀치만 취소하며, 미확정 세션은 파일에 자동 저장하지 않는지 확인합니다.

## 구성과 현재 한계

실제 구현은 `core.py`, `editor.py`, `validation.py`, `storage.py`, `viewer.py`의 다섯 파일로 나눴습니다. `__init__.py`와 `__main__.py`는 얇은 패키지·실행 연결입니다. 계산 코드는 matplotlib에 의존하지 않으며, 미래 음성 입력은 공통 명령 인터페이스를, 3D 손 입력은 `begin_drag`/`update_drag`/`end_drag`를 호출할 수 있습니다.

기하·시간 검사와 모의 입력의 프로토타입입니다. 실제 연속 자세 해석, 관절 한계, 충돌, 관절 속도·가속도, 토크 검사는 수행하지 않습니다. 카메라 보정, 깊이 노이즈, 손 추적 끊김, 실제 장비의 이동 범위와 안전성은 검증되지 않았습니다. 폴리라인 샘플과 가상 카메라를 사용하므로 실제 곡선·영상과의 오차를 별도로 검토해야 합니다. 원본이 바뀔 때의 공간 correction 재사용 계산은 제공하지만, UI에서 새 작업의 원본으로 옮기는 기능은 이번 범위에 포함하지 않습니다.

자동화 검증 결과와 GUI 확인 범위는 [RESULT.md](RESULT.md)를 참고하세요. Agg 렌더링과 합성 이벤트 검증은 사람의 실제 마우스 조작 확인과 구분합니다.
